# 猫出没 产品需求文档

**V0.2 · 2026-11-21 · 作品集审阅稿**  
**载体与范围**　微信小程序，首期课程 / 比赛本地 Demo。本文为开发后回溯整理，沿用原需求与已记录的执行口径，补充优先级、跨模块验收和验证计划。优先级及新增验证方案供本次审阅。

## 1 产品背景与目标

猫出没服务于想认识、查找资料或分享校园猫咪日常的学生与教职工。需求提出者记录了一个具体观察：校园已有「云朵朵」论坛，但缺少专门的猫咪板块。材料中没有相关帖子样本、访谈或问卷记录，无法判断信息分散的频率、用户受影响程度或独立入口的使用意愿。[来源 A1]

| 用户任务 | 当前依据 | 本轮要验证的假设 |
| --- | --- | --- |
| 路过某栋楼，想知道这一带有哪些猫 | 原需求将按区域查猫列为核心场景。论坛板块状况来自提出者陈述 | 用户愿意从楼宇或片区入手，粗粒度区域足以帮助认识猫咪 |
| 看到一只熟悉的猫，想确认名字、别名和相关记录 | 需求、演示种子与测试均覆盖重名、别名。真实校园是否普遍重名暂无资料 | 参考照片、外貌和区域能帮助区分同名猫，用户愿意从档案继续查看帖子 |
| 拍到猫咪日常，想分享并收到互动 | 原需求记录了发布、互动和站内消息场景 | 可选关联减少发布阻力，关联后的帖子对后来查询的人有价值 |

本稿暂以「从已知校园区域找到猫咪档案和关联帖子」为优先验证场景。这是结合已有需求与产品结构提出的本轮排序，尚未证明它比直接浏览帖子更高频或更重要。地图回答「这一带有哪些猫」，图鉴与档案回答「这只猫是谁」，社区回答「大家分享过什么」。档案以稳定 Cat ID 串起地图查询和帖子回流。用户可以从区域进入档案，也可以从帖子中的猫咪 Tag 反查档案。普通帖子允许分享校外猫或暂时无法识别的猫，资料的主要活动区域仍由管理员维护。

### 1.1 方案选择与待验证依据

本轮回溯比较以下三种方案。该比较用于解释当前方案及其代价，不代表项目启动前已经完成竞品研究或方案实验。

| 方案 | 能解决的主要任务 | 局限与代价 |
| --- | --- | --- |
| 在已有校园论坛增加猫咪话题或板块 | 集中发布和交流；可能沿用现有访问习惯 | 能否新增板块、维护固定档案和建立关联取决于论坛能力与运营权限，目前未核实；不能直接认定论坛无法满足需求 |
| 独立猫咪图鉴 | 按名字、照片和区域认识猫，集中维护资料 | 需要持续维护资料；仅有静态档案是否足够、用户是否需要日常内容仍待验证 |
| 地图＋档案＋社区 | 以区域提供发现线索，以档案组织身份信息，以帖子补充日常内容 | 引入独立入口、内容冷启动、资料维护和管理成本；地图及关联操作也可能增加使用负担 |

当前保留第三种方案，是因为它能在一个 Demo 内验证「区域线索能否帮助找到猫」和「身份关联能否让分享内容被再次查询」两项假设。这个选择沿用现有项目范围，不代表已证明独立小程序优于论坛板块。首期以示意选区、稳定档案 ID 和可选关联控制范围，不引入实时定位或自动识猫。

若试用中用户主要按名字或照片查找，区域入口很少帮助完成任务，应降低地图入口优先级；若用户只想看和发帖子，档案关联很少被使用，应重新评估关联成本及独立入口的必要性；若主要问题是资料不足，应先解决资料维护，避免靠新增交互掩盖内容缺口。具体调整以观察记录为依据。

## 2 首期范围与优先级

首期分别支持两类用户任务：

- **认识与查找猫咪：** 游客选区或搜索图鉴 → 找到目标猫咪 → 查看档案及公开关联帖子。用户无需发帖即可完成任务。
- **分享猫咪日常：** 成员编辑图文 → 按需关联猫咪或话题，也可不关联 → 发布 → 查看公开结果。无法识别或校外猫不以建档为发布前提。

跨模块验收再检查「发布关联帖 → 对应档案可见 → 打开同一帖子」，这是验证数据与导航一致性的测试路径，不要求同一用户在一次使用中完成全部步骤。另有已记录的社区互动闭环：浏览 → 评论或回复 → 接收者打开消息回到评论。

下面的 P0/P1 为本次回溯排序，P1 仍属于已记录的首期范围。优先级用于说明用户任务与交付依赖，不代表历史排期已按此执行。

| 优先级 | 范围 | 理由 |
| --- | --- | --- |
| P0 | 地图选区、图鉴与档案、关联帖子、公开首页与详情、登录门槛、发帖和可选关联 | 直接检验能否从区域找到同一只猫，以及分享能否回到档案 |
| P0 | 作者删除、管理员隐藏、公开及个人入口的可见性、越权校验、发布结果未知时防重 | 可见性错误可能暴露受限内容，重复提交可能生成重复帖子；均需在核心交付中验收 |
| P1 | 搜索与七天热帖、点赞、评论回复与消息、头像昵称、个人列表、猫咪区域话题管理 | 支持内容发现、互动和资料维护，其使用价值仍待验证。本地 Demo 使用预置资料时可分开签收；持续试用前需先具备基本资料维护能力 |
| 首期暂缓 | 实时 GPS、导航、AI 识猫、多校、视频、关注收藏、领养交易、支付、发布前审核、编辑已发布帖 | 原文明确排除或暂缓。历史材料仅对 GPS 记录了成本和可行性理由，对支付记录了定位理由。按地点线索推断活动区属于后续研究，方案待核验 |
| 范围待定 | 举报、隐藏恢复、资料删除或归档、正式发布方案 | 已有决策记录保留边界，需先确认政策及外部条件 |

**交付依赖**　本地 Demo 的 P0 查猫流程依赖预先校验的区域、猫档和样例关联，不要求先完成全部管理页面。若进入持续校园试用，必须明确资料维护人、可用维护工具、修改权限及操作记录，并完成基础新增／修改验收；这时基础资料维护属于试用前置条件。评论与通知也必须整体验收接收者及可见性规则，不能以单个页面可打开作为闭环完成。

## 3 角色、入口与返回

| 角色 | 可用操作 | 边界 |
| --- | --- | --- |
| 游客 | 首页、热帖、搜索、公开帖子、地图、图鉴和档案，可进入「我的」查看登录引导 | 发布、点赞、评论、回复、本人内容、消息等操作触发登录 |
| 普通成员 | 游客能力及图文发布、互动、本人资料与列表、消息已读、删除自己的公开帖子 | 个人资源按当前身份读取，只能修改本人资料或消息 |
| 管理员 | 普通成员能力及猫咪、区域、话题的新增/修改、帖子隐藏 | 「我的」出现管理入口，服务端校验角色，角色分配与人员待确认。管理员隐藏与作者删除是两个操作 |

底部固定为 **首页、地图、发布、图鉴、我的**。详情、档案、搜索、消息及管理表单从各自入口下钻。返回优先原页面栈，直接打开档案时回图鉴，个人子页无原页面时回「我的」。受保护操作登录成功后应回到原业务入口，详情保留目标帖子。取消登录仍可浏览。原型为固定画板跳转，运行时以来源栈和实际数据为准。[A1 §3.6；A2 NAV-01；A5 页面与路由]

## 4 功能需求与验收条件

编号 MF-xx 为本稿编号，原设计 AT 编号用于回查。各查询页区分加载、空数据、失败和成功，失败可重试，筛选为空可清条件。提交期间应避免连点。下列验收步骤为演示验收预期，已执行部分见第 6 节。产品规则与验收预期写在本节；实现、分支和历史测试状态统一见第 6 节，来源与画板定位见附录 D。

### MF-01 首页、搜索和热帖 · P0 浏览 / P1 搜索热帖

游客从首页查看最新公开帖子，再经卡片进入详情；可打开搜索、热帖或图片预览。首页按发布时间倒序。搜索按正文、话题名称、关联猫名匹配，话题 Tag 打开相关帖子列表，猫咪 Tag 打开指定 ID 的档案。七天热帖仅统计在查询时点 T 的闭区间 [T−7 天, T] 内发布的公开帖，依次按点赞、评论、发布时间、稳定 ID 降序，最多十条。详情不可用时提示后可返回原列表。

**验收**　准备新旧、同赞同评及隐藏帖子。检查首页顺序、榜单上限及边界，分别以正文、话题和猫名查找，清除无结果条件后恢复。点图片预览并返回原详情或信息流。  

### MF-02 地图、图鉴和档案 · P0

从地图点击示意热区或区域筛选，底部展示该区猫咪，可切到另一片区或清除选区；无对应记录显示「暂无资料」。图鉴支持名字、别名与区域组合筛选。档案展示名字、别名、照片、性别（可未知）、外貌、性格描述、主要活动区域与公开关联帖。性格为观察性资料。缺图使用占位，缺少或无效 Cat ID 提示资料不可用并可返回；关联帖查询失败可独立重试。返回地图应保留有效选区，切区后迟到的旧结果不得覆盖当前列表。

**验收**　以两只同名猫、一个别名、一个空区域和一条多猫帖为夹具。分别经地图及图鉴进入正确档案，检查别名与区域组合、清筛选、空区、错网重试，关联帖跳详情后逐级返回。停在原型示意区域不触发定位授权。  

### MF-03 图文发布与关联 · P0

成员从发布进入编辑，输入正文或添加图片，至少有一项。正文最多 2000 Unicode 码点（验收计数口径），图片最多 9 张，可零或多选有效话题及猫咪；校外猫可直接发布，无需校园档案或遇见区域。Tag 页完成后回填草稿；上传失败保留已有输入并重试；提交成功直接公开，成功页可查看帖子或回首页。无效关联、图片不合规或明确校验失败应给出可改正提示。结果未知时保留原内容及请求标识，允许确认式重试。

**验收**　分别发布纯文、纯图、零 Tag、两只同名猫多选；确认两份档案都可见同一帖子。检查空输入、2000/2001 Unicode 码点、9/10 图、图片归属与上传失败。模拟写入成功但回包丢失，重试后只出现一条相同帖子。  

### MF-04 点赞、评论回复和消息 · P1

成员在公开帖详情点赞或取消，可输入文字评论，也可选一条同帖评论回复。点赞按目标状态写入，同一人对同一帖子最多一条有效点赞；评论回复需要非空文字，当前 Demo 上限为 2000 Unicode 码点。评论通知帖主；回复通知帖主及被回复者，接收者去重且排除操作者。通知只面向接收者。进入列表保留未读，打开单条后已读，也可显式全部已读，随后产生的新消息仍未读。可用目标打开帖子并定位评论；目标被隐藏或删除时可读通知状态，显示内容不可用，留在消息页。失败保留评论输入和回复对象，返回沿原栈。

**验收**　让 A 发帖、B 评论、C 回复 B。检查 A、B 各获对应通知，帖主与被回复者相同时只发一条，自评排除。检查重试不重复写、越权标记拒绝、进入列表不清零、单条/全部已读及隐藏后的提示。  

### MF-05 登录、个人资料和本人内容 · P0 访问边界 / P1 个人工具

游客遇到受保护操作时进入登录，成功后返回原业务入口。真实微信登录及首次设置头像昵称是记录的首期需求；当前具备微信 code 交换及资料设置入口，平台验收单列。Demo 的资料保存要求非空昵称（技术上限 80）和空头像或本人上传的有效头像。我的发布与点赞只查询当前账号的可见记录，取消点赞或删除后刷新应体现结果。退出登录需确认，服务端撤销当前会话后清本地会话；当前请求失败提示并保留会话，离线策略待定。无列表结果显示空态，资料保存失败保留输入。

**验收**　游客从详情点赞触发登录并返回；用两个开发身份验证本人列表隔离、头像归属、失败重试及退出后保护入口。真微信测试单独覆盖已授权账号、首次资料设置入口、取消或失败、再次登录；保存结果与「我的」一致。  

### MF-06 作者删除与管理员隐藏 · P0

作者可在本人公开帖入口确认删除或取消。管理员在「我的 → 管理 → 帖子」选择隐藏，当前原因可空，Demo 上限 500。隐藏或删除完成后，首页、搜索、热帖、档案关联、直接详情、个人发布和点赞及该帖图片链接应统一按可见性过滤；历史通知仅保留必要状态且目标不可用。点过赞或拥有图片资源的身份不会恢复帖子公开访问。当前隐藏帖在本人发布中也不可见，作者直调删除返回策略待定，业务政策待确认。保留必要管理记录，物理删除、留存期限另议。

**验收**　分别以作者与管理员对两条样例帖删除、隐藏，使用另一账号逐入口刷新并直开旧链接；验证图片、通知、非作者删除拒绝、重复操作及隐藏日志。取消删除时继续停留原内容。  

### MF-07 管理资料与并发提交 · P1

管理员从管理入口新增或编辑猫咪、区域与话题。猫咪名称、有效主要区域及性别选项必备（允许未知），别名与照片可空，外貌和性格可缺省。区域录入名称和图上有效矩形范围，话题录入名称与启用状态。停用话题退出新发布的选择列表，仍可在管理端重新启用；历史标签政策待确认。普通成员直接打开管理页或请求接口均应被阻止。修改前提交所读版本，并发冲突提示载入最新记录后再提交。保存及必要日志同进退；保存失败应有反馈，返回优先原栈、无栈回「我的」。

**验收**　新增同名猫并改名换区，核对 ID 与帖子关联、旧区和新区列表。模拟两人同时编辑，迟提交者收到版本冲突。停用话题后验证新发布不可选、管理端仍可查；丢响应后重试同一操作，资料版本和日志最多变化一次。  

## 5 跨模块规则与约束

- **关联**　Area → Cat 为一对多，每猫一个有效主要区域。Post 与 Cat、Post 与话题均为可选多对多。猫名、别名、话题名和帖子正文均是展示或检索线索，关联以 ID 为准。发帖地点不自动更新猫档区域。
- **可见性**　公开读仅返回已发布。隐藏与删除保留必要数据状态。图片发布前按上传归属和用途校验，帖子图片由服务端按有效引用判断公开访问。头像与猫图走各自用途；管理猫档可保留该档已有图片。未引用资源回收、正式图片规格和运营留存政策待定。
- **写入失败**　明确的参数、权限或版本失败应反馈可修正原因。提交结果未知时应重试原操作和相同内容，期间避免改动待确认的提交。发布与评论用幂等标识，点赞用目标状态，管理同标识异内容会被拒绝。PR #5 的管理快照按账号与模块保存，清除小程序本地数据后无法保证恢复。
- **隐私与资料**　权限与资源归属由服务端验证。公开响应不包含微信身份标识或会话凭证。真实地名、示意边界、猫档和照片授权需逐项核验，地图不展示敏感栖息点，不承诺会遇见猫。Demo 采用演示种子与手绘底图，地图浏览不申请 GPS。
- **运行与兼容性**　历史记录覆盖本地 MySQL、真实本地图片读写和电脑微信开发者工具，正式访问条件包括平台账号、HTTPS 合法域名、共享服务与正式图片存储。当前 Demo 图片支持静态 JPEG/PNG/WebP，8 MB 内且最多 2000 万像素，保存时去元数据并缩放，属于本地实现参数。正式环境图片授权、访问控制、缓存后的不可见性、限流与运维责任需进入发布验收；暂无容量、时延或兼容机型承诺。
