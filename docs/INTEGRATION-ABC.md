## 审查结论

三个包均不能原样覆盖工程。以下问题已在集成中修复，没有把原包标成“无问题”。

| 模块 | 原包范围 | 发现的问题 | 集成处理 |
|---|---|---|---|
| A | 两个 JS 页面和独立 request | `.join()` 出现在 WXML；资料照片 ID 被当 URL；详情参数/公共组件事件需对齐；详情分页无重复请求锁，筛选期间返回旧请求可覆盖新条件；独立 request 缺 env 文件和统一登录头 | 保留列表/资料布局，迁为 TS，复用现有 request/api/routes、卡片及状态组件；照片转媒体地址；分页锁和请求代次保护；档案参数 catId，帖子参数 postId |
| B | 五个 JS 页面、另一套 request/routes 与卡片 | 固定 localhost:8080；响应使用 code=200 而非 ok/data；未携带登录头；路径缺 /api/v1；post/login 不在其路由表；展示字段 content/isContentAvailable 与 DTO 不符；没有后端；已读时 loading 阻止刷新；退出未清会话 | 保留个人菜单/设置/列表页面结构，迁 TS 并复用全局公共能力；补真实资料、本人内容、消息、未读数和已读后端；单条打开即已读，进列表不全读；退出撤销服务端会话并清本机登录态 |
| C | 完整工程副本，主要变更是管理前后端及测试 | 大部分只是 CRLF 差异，不能覆盖所有公共文件；使用公开话题列表导致停用后无法重新维护；任何其他管理员旧照片都被拒绝；部分分页缺锁 | 仅提取 admin 目录及其测试；增加管理员全状态话题查询；允许保留当前猫档已关联照片，仍拒绝借用他人未关联上传；补列表请求锁与代次保护 |

B 包包含“简介 bio”，现有已约定 DTO/数据库只有昵称与头像。此次按已有契约实现昵称/真实头像上传，未擅自增加简介字段；如确认需要，另做新增迁移，不修改已应用的 001。B 自带独立公共卡片、app/config/request/routes 均未覆盖当前工程。C 的 scripts/setup.mjs 和本机配置也未采用。

## 实现和数据边界

- A：`miniprogram/features/catalog`，后端复用 `catalog/routes.ts` 和 `posts?catId`；稳定 ID、重名独立、别名/区域组合筛选、关联公开帖子和返回路径。
- B：`miniprogram/features/account`，统一 API 在 `api.ts`；相同的本人帖子/点赞分页行为在 `content-page.ts`。后端 `account/routes.ts`；GET /me 继续在 identity。资料 PUT 移到 account，避免重复注册。
- C：`miniprogram/features/admin` 和 `server/src/modules/admin`；创建/修改猫、区域、话题及隐藏帖；角色由服务端查库；日志和幂等结果与业务写同事务；version 冲突 409。新增 GET /admin/topics 受管理员保护，含停用项。
- 没有更改数据库结构或已有迁移，也没有增加依赖。公开及本人帖子/点赞列表均排除隐藏和删除；隐藏帖作者是否可管理该内容仍待业务确认，当前不显示；通知保留，但不返回旧正文，标明目标不可用。
- 单条已读仅接收者可改；read_at 使用 COALESCE，不因重复操作改变原已读时间。全部已读只更新当前用户当时已有未读记录；随后产生的通知仍未读。未读数由数据库统计。
- PUT /me 是昵称/头像目标状态赋值，可安全重试；头像必须是本人 ready/avatar 资源。POST /auth/logout 只撤销当前令牌。
- 本地开发登录增加“普通成员/管理员”演示选择，仅服务端明确启用开发身份时可见；生产环境仍拒绝该功能。不是微信认证或正式角色分配。
